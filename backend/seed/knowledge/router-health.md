Router Health, Reboot Loop and Coverage Remediation
1.0
## CPE reboot loop and high CPU
A CPE_REBOOT_LOOP alarm or router CPU above 65% usually means the router is overloaded or a process is stuck. Reboot the router remotely first to clear the high CPU usage. After the reboot, confirm the router stays online and the CPU drops back to normal. If the CPU stays high or the router keeps restarting after a reboot, replace the router.
## High memory usage
Router memory above 80% slows down routing and Wi-Fi and can trigger restarts. Reboot the router to free memory. If memory climbs back quickly, check the firmware version and replace the router if it is an outdated model.
## Outdated router model
Routers that are not a current model (AX3000 or BE7200) cannot keep up with modern Wi-Fi traffic. Recommend replacing the outdated router with a current model and re-test throughput afterwards.
## Weak Wi-Fi coverage
When several wireless devices report RSSI below -80 dBm, the Wi-Fi signal does not reach every room. Add a mesh node or repeater to extend coverage, or move the router to a central position. Changing the Wi-Fi channel helps with interference but does not fix distance-based weak signal.
## Wi-Fi channel and interference
If devices near the router still see slow speeds, move the 2.4 GHz radio to a less busy channel (1, 6 or 11) or the 5 GHz radio to a clean channel such as 36, 44 or 149. Change one setting at a time and re-test.
## Plan upgrade for heavy usage
When monthly usage is 1000 GB or more with eight or more end devices on a plan below 1 Gbps, the plan is too small for the household. Recommend upgrading to a higher-speed internet plan. Access points and mesh nodes are not end devices and do not count.
## Weak optical signal
Optical receive power below -28 dBm points to a fibre problem, not the router. Run optical diagnostics and contact the ISP or fibre team about the optical signal before changing router settings.
